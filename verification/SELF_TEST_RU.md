# Как самостоятельно проверить аддон

Рабочая ветка: `codex/input-data-addon` в репозитории IgorCim/GTsimulation.
Основная ветка не заменена. Геомагнитный агент для этой проверки не нужен.

## 1. Детерминированные проверки без сети

В терминале из корня GT с установленными зависимостями и pytest:

```text
python -m pytest tests/test_input_data.py tests/test_input_data_integration.py tests/test_atmosphere_inputs.py tests/test_ta15_inputs.py tests/test_input_data_cli.py -q -W error
```

Ожидается **86 passed**. В нашей Windows-среде отключена автоматическая
загрузка сторонних pytest-плагинов: `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`.
Это не настройка GT. Для нормальной проверки JIT переменная
`NUMBA_DISABLE_JIT` не должна быть установлена.

## 2. Реальные источники

Из корня проекта:

```text
python verification/check_expanded_live.py
```

Проверяются реальная загрузка CelesTrak и T15B, чтение подготовленных данных
моделями GT, конечные значения плотности/поля, совпадение годового источника
T15B с исходной таблицей GT при её точности хранения. Будут созданы новые
папки в verification/live и отчёт verification/expanded_live_result.json.
Старые папки не удаляются. Отчёт последнего запуска заменяется.

Проверка зависит от внешних сайтов. Ошибка TLS, HTTP или отсутствие данных —
причина неуспешной загрузки; нельзя записывать её как успешный тест источника.
Не отключайте проверку сертификатов. Для TA15 программа честно сообщает
ограничение GSW/GSM существующей обёртки GT.

Для самостоятельной загрузки NASA T96:

```text
python -m gtsimulation.input_data --model 96 --start 2024-09-10 --end 2024-09-11 --output-dir my_inputs
```

Ожидаются 24 строки и пути inputs.npy/manifest.json. Интеграционный тест
`test_short_trajectory` проверяет также запись траектории в HDF5.

## 3. Проверка отказа

```text
python -m gtsimulation.input_data --model 15B --start 2023-01-01T00:31 --end 2023-01-01T00:40 --output-dir my_inputs
```

Ожидается ненулевой код завершения и объяснение: границы T15B должны быть
кратны пяти минутам. Сеть для такого запроса не нужна; готовый пакет не создаётся.

## Что значит успешная проверка

Подтверждаются конкретные входы, контракты и сохранение прежнего пути запуска.
«100% всех возможных случаев» тестами доказать нельзя. Не проверены Geant4,
все операционные системы и научная точность всех моделей. Обновление версий
коэффициентов полей, включение IRI и интеграция с агентом сюда не входят.
Полный перечень входов и границ находится в docs/user_guide/input_inventory.md.

## Следующая проверка: NASA, целостность и автономная работа

Сначала выполните check_expanded_live.py, чтобы появились свежие входы атмосферы
и T15B и указатель на них в expanded_live_result.json. Затем:

```text
.venv\Scripts\python.exe verification\check_reuse.py
```

Скрипт скачает реальные T89 и T96 за 2024-09-10 (по 24 часа), проверит SHA256
исходных ответов и inputs.npy для четырёх моделей, выполнит вычисления в двух
новых процессах и сравнит результаты с rtol=1e-10, atol=1e-12. Во втором процессе
аудит Python блокирует сетевые соединения и DNS до импорта GT. Даже перехваченная
внутри библиотеки попытка обращения к сети считается провалом проверки.
Это проверяет Python-вызовы сети в данной цепочке, а не изоляцию всей ОС.

Успешный итог: `PASS: live T89/T96, bundle SHA256, offline reuse of 89/96/15B/NRLMSIS.`
В конце выводится путь к уникальному verification/reuse-.../report.json.
При отказе в той же папке сохраняется FAIL с причиной. Новые ответы NASA
сохраняются даже при ошибке парсера. Скрипт не исправляет ответы провайдера.
Предыдущие папки и отчёты не заменяются.

Контрольные суммы проверяет этот скрипт; это не утверждение, что конструктор
GT автоматически проверяет манифест при каждом чтении. Допуски сравнения
проверяют воспроизводимость на этом компьютере, а не физическую точность моделей.

Сам проверочный механизм имеет четыре теста: корректные суммы, изменение
входного файла, изменение исходного ответа и блокировка сетевого соединения:

```text
.venv\Scripts\python.exe -m pytest tests/test_input_reuse.py -q -W error
```

## Независимый пересчёт входов

После успешного check_reuse.py:

```text
.venv\Scripts\python.exe verification\check_independent_inputs.py
```

Скрипт автоматически выбирает самый свежий успешный reuse-прогон. Для конкретного:

```text
.venv\Scripts\python.exe verification\check_independent_inputs.py --bundles verification\reuse-5z9jejcq\bundles.json
```

Он не импортирует GT, его загрузчик или pymsis. Отдельным чтением исходников
проверяются все временные метки и значения: явные группы Kp для T89; Pdyn,
Dst, By/Bz GSM для T96; Pdyn, By/Bz GSW, B-index и флаги для T15B; F10.7
предыдущего дня, среднее CENTER81 источника и семь параметров Ap для NRLMSIS.
Исторические средние Ap вычисляются прямым суммированием восьми значений
за 12–33 и 36–57 часов до текущего трёхчасового окна.

Ожидаемый итог: `PASS: independent input audit for 89/96/15B/NRLMSIS.`
Подробности, первые ожидаемые значения и максимальные ошибки каждого столбца
сохраняются в новом verification/independent-.../report.json.

Допуск сравнения чисел: абсолютный 1e-12, относительный 0; время и флаги
должны совпасть точно. Механизм имеет 16 тестов:

```text
.venv\Scripts\python.exe -m pytest tests/test_independent_inputs.py -q -W error
```

Эта проверка независима по реализации чтения и вычисления входов. Она не
проверяет независимыми наблюдениями сами данные провайдера, не пересчитывает
его CENTER81 из 81 дня и не доказывает физическую точность моделей или
преобразований GSW/GSM. Связь с описанием NASA:
https://omniweb.gsfc.nasa.gov/html/ow_data.html
Формат TA15: https://geo.phys.spbu.ru/~tsyganenko/models/ta15/Data_format.txt
Определения предыдущего дня F10.7 и истории Ap соответствуют интерфейсу
get_f107_ap установленного pymsis 0.13.0; расчёт в этой проверке написан отдельно.

## Отказы и восстановление

```text
.venv\Scripts\python.exe -m pytest tests/test_input_recovery.py -v -W error
```

Ожидается 28 passed. Это воспроизводимые искусственные отказы, внешние сайты
не вызываются. Для каждой из четырёх моделей сначала создаётся успешный пакет,
затем вводится отказ, затем повторяется корректный запрос в том же процессе и
каталоге. Проверяются таймаут, HTTP 404, исчерпание повторов HTTP 503, повреждённый
ответ, отсутствие обязательного времени/дня и ошибка записи. Для атмосферы ошибка
записи моделируется ненулевым завершением рабочего процесса, а не реальным
заполнением диска. Дополнительно проверяется 503 с успехом на второй попытке.

После отказа не должно быть новых файлов или оставшихся staging-каталогов.
Все байты ранее созданного пакета должны сохраниться. Последующий успешный
запрос создаёт отдельный корректный пакет, численно совпадающий с первым.
Количество сетевых попыток проверяется: 404 не повторяется; таймаут и 503
ограничены заданными двумя попытками.

Полный набор проверок аддона (134 случая):

```text
.venv\Scripts\python.exe -m pytest tests/test_input_data.py tests/test_input_data_integration.py tests/test_atmosphere_inputs.py tests/test_ta15_inputs.py tests/test_input_data_cli.py tests/test_input_reuse.py tests/test_independent_inputs.py tests/test_input_recovery.py -q -W error
```

Для записи XML добавьте `--junitxml=verification/my-addon-tests.xml`.
Эти тесты не имитируют аварийное выключение компьютера или повреждение диска ОС.
