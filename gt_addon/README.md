# Самостоятельный аддон загрузки входных данных GT

**[Инструкция для пользователей: установка, четыре загрузки и просмотр чисел](USER_GUIDE.md)**

[Логи четырёх реальных пользовательских запусков](evidence/2026-11-21-user-runs/README.md) · [Все тесты и доказательства](TESTING.md)

Весь рабочий код находится в `fetcher.py`. Папку `gt_addon` можно копировать
отдельно от GT. Аддон не импортирует `gtsimulation`, не запускает симуляции,
не меняет классы, коэффициенты, системы координат или файлы установленного GT.
Скачанные файлы сохраняются в явно указанный пользователем каталог.

## Что делает

- NASA OMNI2: почасовые входы T89 (категория Kp) и T96 (Pdyn, Dst, By/Bz GSM).
- Официальные TA15: пятиминутные входы T15B, By/Bz GSW и B-index;
  флаги интерполяции источника сохраняются. Без явного разрешения флаг 2 запрещён.
- CelesTrak: наблюдённые F10.7/Ap для NRLMSIS. История индексов готовится
  библиотекой pymsis в отдельном процессе; её настройки в родительском процессе
  не меняются. Сохраняются исходный CSV и выбранные дни с необходимой историей.

Пакет результата: исходные ответы, числовой `inputs.npy` и `manifest.json`
с UTC-интервалом, единицами, источником, датой получения и SHA256. Каждый вызов
создаёт новый каталог. Пропуски не интерполируются и не заменяются другими данными.
NPY читается с `allow_pickle=False`. Неполный пакет после обработанной ошибки удаляется.

## Установка и использование в Windows

Из корня этой копии репозитория (Python 3.10 или новее):

```bat
python -m venv gt_addon\.venv
gt_addon\.venv\Scripts\python.exe -m pip install ./gt_addon pytest
```

Если окружение уже подготовлено, повторно создавать его не нужно.
Пример загрузки T96:

```bat
gt_addon\.venv\Scripts\python.exe gt_addon\fetcher.py --model 96 --start 2024-09-10 --end 2024-09-11 --output-dir gt_addon\inputs
```

Выбор `--model`: `89`, `96`, `15B`, `nrlmsis`.
Для T89/T96/NRLMSIS границы должны быть целыми часами UTC, для T15B — кратны
пяти минутам. Интервал `[start, end)`: начало включено, конец исключён; до 366 дней.
Зональные ISO-даты переводятся в UTC, даты без зоны считаются UTC.
Параметр `--allow-provider-interpolation` допустим только для T15B.
После установки доступна также команда `gt-fetch`.

Python API установленного пакета:

```python
from fetcher import download_tsyganenko_inputs
result = download_tsyganenko_inputs(
    "2024-09-10", "2024-09-11", "my_inputs", model="96"
)
print(result["input_file"], result["manifest"])
```

Другие функции: `download_ta15_inputs` и `download_atmosphere_inputs`.
Аддон выдаёт файлы, но не добавляет GT параметр `input_file` и не подключает
результаты к модели автоматически. Применение файлов в научном расчёте
контролирует пользователь/разработчик GT. Параметры моделей GT здесь не изменены.

## Проверка

Детерминированные тесты (интернет не нужен):

```bat
set PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
gt_addon\.venv\Scripts\python.exe -m pytest gt_addon\tests -q -W error
```

Ожидается 190 passed: прежние 174 проверки и 16 дополнительных проверок конкурентного кэша Windows. Проверяются форматы, значения, UTC, пропуски, безопасность
NPY, повторные попытки, 404/503/таймауты, ошибки записи, сохранность прежнего
пакета, восстановление после отказа, отсутствие импорта GT и работа CLI.
Тесты физических моделей исключены: аддон их не исполняет.

Реальная загрузка четырёх моделей и независимый пересчёт чисел из исходников:

```bat
gt_addon\.venv\Scripts\python.exe gt_addon\tests\check_live.py
```

Результаты сохраняются в `gt_addon/results/live-.../report.json`.
Ошибка внешнего сайта отмечается FAIL, а не считается успешной загрузкой.
Можно повторить только один источник: добавьте `--models nrlmsis`.
Для честного повторного прогона сохранённых ответов используйте
`--replay-dir "путь/к/каталогу/с/исходными/пакетами"`. Скрипт сверяет их
старые SHA256, явно выводит режим offline replay и не выдаёт его за новую загрузку.
Ветка теста T15B явно разрешает интерполяцию источника и сохраняет её флаги.
Проверка не импортирует GT и не вызывает его физические модели.

## Научные границы

Системы координат источника не преобразуются: T96 By/Bz — GSM, T15B — GSW.
Загрузчик не сертифицирует согласованность координат последующего расчёта GT.
Kp имеет исходный шаг три часа; почасовая таблица не делает его почасовым
измерением. Атмосферные F10.7/F10.7a/Ap — суточные, ap — трёхчасовой;
почасовое сохранение не повышает исходное разрешение.

Для T15B соблюдается существующий предел B-index 0..2, для атмосферных входов
прогнозные/неполные записи отклоняются. Новые драйверы не расширяют срок
действия коэффициентов физических моделей. Доступность всех дат не гарантируется.
Проверка сертификатов TLS не отключается; при ошибке сертификата загрузка
завершается отказом. Сервис TA15 может отдавать неполную цепочку сертификатов,
поэтому доступность зависит также от доверенного хранилища среды.

## Наглядный полный прогон

```bat
gt_addon\.venv\Scripts\python.exe gt_addon\tests\run_visible_checks.py
```

Сначала выполняются все автотесты, затем четыре проверки источников по отдельности.
Для CelesTrak допустим проверенный кэш младше трёх часов; его использование и
исходное время получения явно указаны в отчёте.
В консоли каждые пять секунд видны модель и длительность ожидания. По умолчанию
на источник отведено 180 секунд; `--timeout 60` задаёт меньший лимит проверки.
Это лимит внешнего проверочного процесса, а не изменение сетевого кода аддона.
После таймаута останавливается дерево только запущенной им проверки.

С первой строки выводится путь к `gt_addon/results/visible-.../report.html`.
Откройте этот файл двойным щелчком в Проводнике; F5 обновляет его во время работы.
Для каждого успешного источника видны UTC-интервал, число строк, первая ожидаемая
строка, первые пять фактически сохранённых строк, максимальные ошибки сверки и
ссылки на CSV со всеми строками и журналы. Интернет для просмотра отчёта не нужен.
Время конца интервала исключено. Единицы указаны в названиях столбцов.

PASS требует успешных автотестов и всех выбранных источников. TIMEOUT/FAIL/ERROR
не выдаются за успешную загрузку. `--skip-unit --models nrlmsis` позволяет отдельно
проверить CelesTrak, но такой отчёт имеет PARTIAL при успехе источника и не считается
полной приёмкой. Зелёный результат конкретного прогона не доказывает отсутствие
любых ошибок на всех датах и при любых внешних сбоях.


## Исправление передачи CelesTrak (1.0.1)

Для недавних интервалов выбирается официальный `SW-Last5Years.csv`, для старых —
`SW-All.csv`. При выборе учитываются три предшествующих дня истории, а фактическая
полнота каждого дня всё равно проверяется. В API `dataset="all"` или `"recent"`
позволяет явно выбрать файл; неподходящее покрытие приводит к отказу.
Фактические URL и имя исходного файла записываются в манифест.

CSV передаётся HTTP-диапазонами по 64 КиБ. Проверяются Content-Range, длина части,
общий размер и один сильный ETag. Смена версии файла, неверные смещения или
неполные части не принимаются. Если сервер сразу вернул целый файл (HTTP 200),
он принимается только как полный ответ с проверкой размера. После начала сборки
такой ответ отклоняется: старую и новую версии смешивать нельзя. Ограничения
403 не обходятся; длительный Retry-After не игнорируется. TLS остаётся включённым.

[CelesTrak просит скачивать данные только по необходимости и один раз за обновление](https://celestrak.org/usage-policy.php);
для space weather указано обновление каждые три часа. Поэтому CLI и проверочный
прогон используют явный кэш не старше трёх часов. Он не подменяется устаревшим
файлом при отказе сайта. Кэш проверяется по SHA256, а данные повторно проверяются
на наличие запрошенного интервала. В манифесте и отчёте видны `source_mode`
(`network` или `validated_cache`) и исходное `source_retrieved_at`. Время получения
не заменяется временем повторного вызова. `created_at` — время создания нового пакета.

Кэш CLI: `.celestrak-cache` внутри указанного output-dir. У проверочного прогона
он находится в `gt_addon/inputs/.celestrak-cache`. Python API включает кэш только
при явной передаче `cache_dir`; для нескольких выходных проектов можно использовать
один общий каталог. Без кэша вызов означает новую сетевую загрузку, поэтому
ответственность за частоту запросов остаётся у вызывающей программы.

Пример повторного использования в API:

```python
from fetcher import download_atmosphere_inputs
result = download_atmosphere_inputs(
    "2024-09-10", "2024-09-11", "my_inputs",
    cache_dir="my_inputs/.celestrak-cache"
)
print(result["source_mode"], result["source_retrieved_at"])
```

PASS при `validated_cache` означает проверенную подготовку входов из явно
указанного кэша, а не новый контакт с сайтом. В HTML это помечено для источника.
При текущем недоступном сайте и отсутствующем/просроченном кэше загрузка должна
честно завершиться ошибкой. Изменения относятся только к аддону передачи данных;
GT, NRLMSIS, формулы истории F10.7/Ap и преобразования координат не менялись.

## Исправление конкурентного кэша Windows (1.0.3)

При одновременной работе Windows может временно запрещать чтение или атомарную
замену файла кэша. Для этих операций добавлены максимум восемь попыток с короткими
паузами. Постоянная ошибка не скрывается. Идентичный CSV с адресацией по SHA256
повторно не заменяется; существующее содержимое проверяется. Сохраняется атомарная
публикация метаданных, старый опубликованный кэш остаётся читаемым при отказе.

190 тестов исходников и установленного пакета прошли; конкурентный набор повторён
20 раз, включая четыре независимых процесса и одновременных читателей/писателей.
[Исходный отказ, новые тесты и журналы](TESTING.md#исправление-конкурентного-кэша-windows-103).
