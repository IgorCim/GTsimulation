## Что нашли новые тесты и что исправлено

Три новых случая сначала завершились ошибкой теста: процесс подготовки NRLMSIS
якобы успешно возвращал массив с другой датой, меньшим или большим числом часов.
Схема и непрерывность были правильными, но принадлежность запрошенному интервалу
не проверялась. Это искусственно воспроизведённый дефект защиты; не свидетельство
того, что ранее скачанные реальные входы имели неверную дату.

В 1.0.2 после чтения результата процесса добавлено точное сравнение всех UTC-меток
с запрошенным `[start, end)`. Неверный пакет отклоняется и удаляется до публикации.
Формулы и настройки pymsis не менялись.

[Первоначальный результат: 28 PASS и 3 FAIL](evidence/2026-11-21/new-tests-before-fix.xml).
После исправления все три случая и прежние тесты прошли.
Также тестовый офлайн-стенд научили читать оба официальных CSV CelesTrak вместо
обязательного SW-All.csv. Это изменение тестового стенда, не модели GT.

## Как повторить самостоятельно и увидеть работу

Команды ниже — для **cmd Windows**, из корня копии проекта.

### 1. Проверить окружение

```bat
cd /d "C:\Users\User\Desktop\GTsimulation-addon-dev"
gt_addon\.venv\Scripts\python.exe -m pip show gt-input-addon
gt_addon\.venv\Scripts\python.exe -m pip check
```

Ожидается Version: 1.0.2 и `No broken requirements found.`.
Текущее локальное окружение уже обновлено. Для новой установки:

```bat
python -m venv gt_addon\.venv
gt_addon\.venv\Scripts\python.exe -m pip install ./gt_addon pytest
```

### 2. Все автоматические проверки исходников

```bat
set PYTEST_DISABLE_PLUGIN_AUTOLOAD=1
set GT_ADDON_USE_INSTALLED=
gt_addon\.venv\Scripts\python.exe -m pytest gt_addon\tests -v -W error -p no:cacheprovider
```

Вы увидите имя каждого случая и `PASSED`; итог — **174 passed** без skipped,
failures и errors. Интернет не нужен, кроме локального HTTP на 127.0.0.1 внутри
одной проверки. Ожидаемые отказы сайтов в этих тестах искусственные.

### 3. Те же проверки установленного пакета

```bat
set GT_ADDON_USE_INSTALLED=1
gt_addon\.venv\Scripts\python.exe -I -m pytest gt_addon\tests -v -W error -p no:cacheprovider
set GT_ADDON_USE_INSTALLED=
```

Ожидается **174 passed**. Это отдельная проверка установленной поставки.

### 4. Наглядный прогон с реальными источниками

```bat
gt_addon\.venv\Scripts\python.exe gt_addon\tests\run_visible_checks.py
```

Первая строка — путь к **вашему новому** HTML-отчёту. В консоли каждые пять секунд
видно, какой источник проверяется и сколько он ждёт. Нормальный итог:
`АВТОТЕСТЫ: PASS; 174`, четыре строки `ИСТОЧНИК ...: PASS`, затем `ИТОГ: PASS`.
Источник может ждать десятки секунд; через 180 секунд проверка останавливается
и честно показывает TIMEOUT. При TLS/503/таймауте FAIL не означает неверную физику,
но свежая загрузка этого запуска не подтверждена. Не удаляйте такой лог.

Откройте Проводник и вставьте выведенный путь `...\report.html` в адресную строку.
На странице видны ожидаемая первая строка, первые пять **реально записанных** строк,
ошибки сверки, число строк, UTC-интервал и ссылки на CSV и логи. При открытии во
время работы нажмите F5. Из CSV можно глазами прочитать все значения.
GitHub показывает исходник HTML; для просмотра страницы скачайте репозиторий и
откройте HTML локально. Страница TESTING.md и CSV читаются прямо на GitHub.

В соседних `results/live-...` находятся исходный ответ сайта, `selected.csv` для
NRLMSIS, `inputs.npy` и `manifest.json`. Точный каталог указан в JSON отчёте.
В манифесте проверьте источник, SHA256, UTC и режим `network`/`validated_cache`.
Кэш CelesTrak нельзя выдавать за новую сетевую загрузку. Не нужно удалять его
ради зелёной надписи: повторное использование в пределах трёх часов ожидаемо.

### 5. Повторить подготовку без сети из своих сохранённых исходников

После успешного реального прогона:

```bat
gt_addon\.venv\Scripts\python.exe gt_addon\tests\check_live.py --replay-dir gt_addon\results
```

Ожидается `MODE: offline captured-response replay`, четыре успешных проверки,
`SOURCE nrlmsis: offline_replay`, затем `PASS: offline captured-response replay`.
Стенд проверяет исходные SHA256 перед повтором. Если сохранённые файлы изменены,
он должен отказаться, а не скачать замену. Этот режим проверяет подготовку входов,
не текущую доступность сайтов. На чистой машине сначала нужен шаг 4.

### 6. Дополнительная диагностика NASA, только если снова возникнет TLS-ошибка

```bat
gt_addon\.venv\Scripts\python.exe gt_addon\tests\compare_nasa_download.py
```

Будут четыре ограниченные попытки в порядке прямое → аддон → аддон → прямое,
один URL, один интерпретатор, одинаковые сетевые настройки, одна попытка на случай,
без кэша и с TLS-проверкой. Лог содержит размеры и SHA256 успешных файлов.
Одинаковый отказ у обоих методов указывает на общую проблему соединения, но не
определяет, закрыл его сервер или промежуточная сеть. Сетевые отказы не скрываются.

## Границы подтверждённого результата

**Весь описанный автоматический набор и итоговый прогон прошли.** Это не обещание
отсутствия любой ошибки на любой дате, ОС или версии зависимости. В этой работе
не выполнена отдельная матрица Linux/macOS/Python-версий, не перебраны все годы
архивов и не сертифицированы физические модели GT, Geant4 или согласование GSW/GSM.
Эти задачи не входят в маленький загрузчик. Сторонний сайт может отказать и после
успешного теста; правильное поведение аддона — ограниченный и явный отказ.
